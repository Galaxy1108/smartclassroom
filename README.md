# Classroom Enhancement 智慧课堂

> 本项目代码完全由 AI 生成，仅经过基本人工验证

跨平台（Linux / Windows）教室应用 + 配套 ClassIsland 插件。

- `src/App/` — Avalonia + Fluent 主应用（类 WinUI3 外观）：作业墙、事件队列、课件弹窗、设置页（含 SnowLuma 下载器）。
- `src/Core/` — 跨平台类库：OneBot QQ 接入、AI 网关、教师映射、规则引擎（召唤/作业/换课）、通知排队、文件归档、课件索引、SnowLuma 管理。
- `src/Contracts/` — App 与插件共享的 DTO + JSON Schema。
- `src/ClassIslandPlugin/` — net8.0 纯托管 ClassIsland 插件：提醒渠道、localhost 执行接口、换课合法性校验与落课。
- `tests/Core.Tests/` — 核心逻辑单测。
- `tests/App.Tests/` — headless（Avalonia headless）界面与视图模型单测，含真实渲染的配色断言。
- `tools/ui-preview/` — 可选的 headless 截图工具（不在解决方案内）。
- `docs/` — 方案与设计文档。

## 架构速览

```text
班级QQ ──OneBot WS──▶ App/Core ──AI──▶ 决策 ─┬─ 召唤/换课驳回 ──localhost HTTP──▶ 插件 ──▶ ClassIsland 通知/换课
   │   └─ 文件事件 ──下载归档──▶ 当天课件索引 ──上课事件──▶ 弹窗"您可能需要的课件"
   └─ ClassIsland 未运行时：App 内横幅 + 系统通知降级（Win/Linux 一致）
```

详细设计见 [`docs/plan-v4.md`](docs/plan-v4.md)。

## AI 引擎（双选）

设置页「AI → 接入引擎」二选一，随时切换、改动即存：

| 引擎 | 说明 | 依赖 |
|---|---|---|
| 内置直连（默认） | 直接 POST 到 OpenAI 兼容的 `/chat/completions`，零额外依赖 | 无 |
| pi-ai（Node 边车） | 经 Node 子进程使用 [`@earendil-works/pi-ai`](https://www.npmjs.com/package/@earendil-works/pi-ai)：自带 provider 与模型目录（41 个 provider）、统一鉴权与用量统计 | **Node ≥ 22.19** |

pi-ai 是 TypeScript/npm 包，.NET 无法直接引用，因此做成 stdio JSONL 边车（`tools/ai-sidecar/sidecar.mjs`）：
主程序 spawn Node，按行收发 JSON。边车崩溃会自动重启；任何失败都转成 `AiException`，上层按"保守降级"处理
（召唤排队、作业/换课转人工），不会让应用崩。

- 打包：Linux 包依赖 `nodejs`；Windows zip 需用户自备 Node ≥ 22.19（或安装 SnowLuma 完整版，其内置 Node 会被自动复用）。
- 自检：`tools/mock-openai.py` 是本地假端点，用于不花钱验证自定义 baseUrl 链路。

### 实测可用的服务商：OpenCode Go（opencode.ai）

设置页「服务商」里有 **OpenCode Go（opencode.ai）** 预设（`https://opencode.ai/zen/go/v1`），
两条引擎路径都已用真实 key 跑通（召唤/作业/换课三个任务全部返回正确结构化 JSON）：

| 引擎 | 配置 | 说明 |
|---|---|---|
| 内置直连 | 服务商选 OpenCode Go + 模型 `deepseek-v4.1-flash` | 直接 POST `/chat/completions` |
| pi-ai 边车 | provider 选 `opencode-go` + 模型同上 | 走 pi-ai 目录（41 个 provider） |
| pi-ai 边车 | 服务地址填 `https://opencode.ai/zen/go/v1` | 等价于自定义端点 |

**踩过的坑（已修）**：opencode.ai 的端点要求每个请求带 `x-opencode-session` 路由头，否则返回
`400 {"type":"MissingSessionID"}`。而 pi-ai 只在拿到 `sessionId` 时才补这个头 —— 边车以前不传，
于是请求全被拒；更糟的是 pi-ai 把失败折叠成"空内容 + 结束原因: error"，
界面上只看到"AI 返回了空内容…建议改用非推理模型"，完全指不到真正的原因。
现在：内置直连与边车都会带会话头（自定义 baseUrl 时由边车手工注入），
并且**失败时优先透出 pi-ai 记录的真实原因**（HTTP 状态 + 响应体 + 一句该怎么办）。

想不经过 App 直接定位 AI 问题，可以用边车的手动驱动：

```bash
OC_KEY=xxx node tools/ai-sidecar/drive.mjs providers
OC_KEY=xxx node tools/ai-sidecar/drive.mjs models opencode-go
OC_KEY=xxx node tools/ai-sidecar/drive.mjs complete opencode-go deepseek-v4.1-flash
OC_KEY=xxx node tools/ai-sidecar/drive.mjs complete "" deepseek-v4.1-flash https://opencode.ai/zen/go/v1
```

token 由插件首次启动时在 ClassIsland 配置目录的 `smartclassroom.bridge/bridge.token` 生成，

## 「事件」页是什么

两条用途：

1. **待处理（有出口）**——AI 失败或返回非法时，**群消息不会被丢掉**：原文、发送者、失败原因都留在待处理区，
   可以「重新解析 / 手动录入 / 忽略」。手动录入的作业直接上墙；手动录入的换课**仍走插件合法性校验**，
   不会绕过校验直接改课表。输入非法（如作业科目为空）时不会消费掉这条记录。
2. **决策时间线**——记录应用对每条群消息做了什么、为什么没做（召唤为何排队、AI 判定非召唤、换课是否被驳回、
   QQ 断线重连、课件弹窗失败、崩溃等）。这是排查"老师说了话但没反应"的第一现场。

时间线**跨重启保留**（和作业、待处理一起写进 `state.json`，保留最近 200 条），因此不会自己消失；
要清掉用时间线右上角的「清空」。前 200 条以外的旧记录会被自动挤掉，也不适合当日志长期留档。

### 时间线的配色与复制

每条记录带**严重级别**，界面按级别着色（配色定义在 `App.axaml` 的主题字典里，浅色/深色各一套）：

| 级别 | 颜色 | 什么时候出现 |
|---|---|---|
| 信息 | 蓝 | 正常流程、状态恢复、AI 判定后按预期跳过 |
| 成功 | 绿 | 已归档 / 已上墙 / 已发通知 / 换课已执行 |
| 警告 | 橙 | 功能未启用、QQ 断线重连中、换课非法转人工、AI 降级、大文件待确认 |
| 错误 | 红 | 异常（崩溃兜底）、归档失败、解析失败、提交失败 |

复制有两条路：每行右侧的「复制」按钮复制单条（`[时间] [级别] 来源 · 标题` + 缩进明细），
右上角「复制全部」导出整段（带头部与条数）。正文同时是可选中的文本（`SelectableTextBlock`），
可以像普通文档一样拖选复制；刷新做了指纹比较（数据没变不重建行），所以拖选不会被 2 秒定时刷新打断。

崩溃日志会**把 `AggregateException` 拆开**：外层那句"有任务的异常没人观察"没有任何信息量，
现在直接显示真正的内层异常与第一条栈帧（例如托盘 D-Bus 注册失败的
`org.freedesktop.DBus.Error.ServiceUnknown`）。

## 功能开关：默认全部关闭

装完**什么都不会做**——不会被读群消息后自动发通知、改课表、下文件。五个开关在
设置页最上方，逐项开启（开启即保存，重启生效）：

| 开关 | 开启后做什么 | 关闭时 |
|---|---|---|
| 召唤通知 | 「xxx 来一下」→ ClassIsland 通知（上课排队，带「现在」立刻发） | 不发通知 |
| 作业自动录入 | AI 整理老师作业上墙到「作业」页 | 不上墙（可用「手动添加作业」） |
| 换课自动处理 | AI 解析后交插件校验，**合法才落课**（临时层） | 绝不下发到插件 |
| 群文件自动归档 | 老师发的文件按**科目**分类下载 | 连取下载直链都不做 |
| 上课课件弹窗 | 上课时弹「您可能需要的课件」 | 不弹 |

未开启的功能命中关键词时，事件页会记一条「『xxx』未启用，已跳过」（同类只提示一次，不刷屏），
这样"老师说了话但没反应"有据可查。

### 前置依赖：集成没配好就不允许开启

这些开关都依赖外部集成，依赖不满足时开着也只是空转（收不到消息 / 发不出通知），
所以设置页会**禁用对应开关并写明缺什么**，绕过界面直接赋值也会被拒绝、不会落盘：

| 开关 | 前置依赖 |
|---|---|
| 召唤通知 / 作业自动录入 | QQ 连接（OneBot 地址 + 监听群号）、AI（模型，内置直连还要服务地址） |
| 换课自动处理 | 上面两项 + ClassIsland 集成（桥接 token） |
| 群文件自动归档 | QQ 连接（不需要 AI） |
| 上课课件弹窗 | ClassIsland 集成（不需要 QQ/AI） |

依赖是**动态**判定的：把群号清空，已开启的「召唤通知」会被自动关掉并记一条日志，
避免留下"看起来开着、其实空转"的状态。缺什么直接写在对应开关下面（开关同时置灰），
不再单独放一条总览提示——那只是把同样的字再说一遍。

## 上课课件弹窗：没有当天该科的课件就不弹

弹窗触发链路是「ClassIsland 上课事件 → 当前课次科目/老师 → 当天归档课件」。

- **没有课件就不弹**（不会弹一个空窗口）。
- **只弹当天的、当科的**：同一科目才算命中；昨天/别的科目的文件不会被翻出来。
  科目来自教师映射（归档时写进 `meta.json`）；课表没给科目时会用教师映射里的科目补，
  都补不出来就**不弹**（宁可少弹，也不要上数学课弹语文课件）。
- 认不出科目（`未分类`）的文件，只有在能确认是**本节课这位老师**发的时才会一起弹出。
- 同一节课（日期+科目）只弹一次。

「课件」页的「预览」按钮与设置页「上课课件弹窗 → 测试弹窗」都可以**手动弹一次**（空列表也照常打开并显示空状态），
不需要真的等到上课，也不会受功能开关/课表限制。

## 持久化

作业、待处理事项、事件时间线写入 `state.json`（`~/.local/share/SmartClassroom/`），
30 秒定时 + 退出时落盘，写入用「临时文件 + 原子替换」。手动添加作业后立即落盘。

选 JSON 而非 SQLite：数据量小、零额外依赖、不引入 SQLite 原生库、出问题可直接打开看。
坏文件不会导致启动失败，会另存一份 `.bad` 供排查。

### 为什么"填好的 API Key 更新后又没了"

设置页与 Runtime 以前各持一份 `AppSettings`：设置页把 key 写进 `settings.json`，
而退出时 `Runtime.Stop()` 又拿**启动时装载的那份旧快照**覆盖了同一个文件 ——
于是每次正常退出（更新、重启）都会把本次会话的改动回滚。现在两者共用同一个对象，
退出时的再存一次只是把同一份数据写回，不可能互相覆盖。

顺带修掉两个相关坑：

- **手打的字段不用"碰巧触发别的保存"才落盘**：服务地址 / API Key / 模型 / 群号 / token / 端口
  改成 600ms 防抖自动保存；切页、关窗口、退出前会立刻 `FlushPendingSaves()`。
- **`settings.json` 也改成原子写入**，解析失败时把坏文件留成 `.bad`，
  不再"默默当没配过"——那等于把 Key 一起丢掉。

## 设置页的操作反馈（应用内通知）

启动/停止 SnowLuma、下载 Node、AI 连通性测试、插件探测、保存设置这些**有副作用且耗时**的操作，
完成后都会在**右下角浮出一条应用内通知**（可手动关闭，5 秒自动消失）。
以前这些操作只有设置页里一行小字，用户看不到 → 以为点了没反应、以为失败。

通知复用 `NoticeBar` 的严重级别配色，所以一眼能看出是成功还是失败：

| 级别 | 颜色 | 例子 |
|---|---|---|
| 成功 | 绿 | SnowLuma 已停止 / AI 可用 / 设置已保存 |
| 警告 | 橙 | 已注入但服务未就绪 / 注入的账号与所选不一致 |
| 错误 | 红 | SnowLuma 启动失败 / AI 测试失败 / 打开目录失败 |

### 启动/停止/探测：按钮会转圈

SnowLuma 启动后要等 5 秒才探测、停止也要几百毫秒。这段时间三个按钮会**禁用并显示转圈**
（`启动中… / 停止中… / 探测中…`），避免"点了没反应"的错觉。

### 状态不再是含糊的一句话

运行状态、ClassIsland 连接状态、AI 测试结果都改成**图标 + 文案**的徽标（`StatusBadge`）：

- **对钩（绿）**= 在线 / 已连接且课表已加载 / AI 可用
- **感叹号（橙）**= 已注入但服务未就绪 / 插件连上但课表未加载
- **叉（红）**= QQ 未运行 / 未安装 / 探测失败 / AI 失败
- **信息（蓝）**= 探测中 / 未检测

原来的「已注入 / 服务未就绪」看不出算不算成功，现在用图标把三态分开。

## 风险确认改成弹窗

「我已知晓风险」不再是一个随手能勾的小方框，而是**按钮 + 弹窗**：
点「启动」时若还没确认过，会先弹出完整封号警告，确认后才继续启动；
确认过之后按钮变成「重新查看」，随时能再读一遍原文。

## 班级 QQ 账号：多账号时选一个

一台机器上登过好几个 QQ 号时，"注入到哪个号"是必须明确的。设置页「QQ 连接 → 班级 QQ 账号」：

- 点「检测并选择账号」→ 先通过 OneBot `get_login_info` 检测当前在线的账号，
  再弹窗列出**检测到的 + 以前用过的**账号（在线的那个会标「当前在线」），选一个；
- 检测不到（OneBot 没连上）时也能从候选里选，或直接手动输入 QQ 号；
- 选择会记住（`qqAccount` + `qqAccounts`），探测时若发现**在线账号与所选不一致**会弹橙色提醒；
- 顺带补上了 **OneBot Token** 输入框（以前 `settings.json` 里有这个字段但设置页填不了，
  SnowLuma 配了 access token 就连不上）。

## 课件页：科目 → 时间轴

「课件」页分两层：

1. **科目卡片**：按科目分组，显示该科目的文件数与最近归档时间（没有科目的进「未分类」）；
2. **点进科目 → 时间轴**：按天分组（`2026-09-26 周六`），天内按**归档时间倒序**，
   左侧是时间轴竖线与圆点，行上是 `HH:mm` + 文件卡片（缩略图/类型徽标 + 文件名 + 大小），
   双击打开。「← 返回科目」回到第一层。

归档时间来自每个文件的 `meta.json`（`time` 字段）；老记录没有时间时归到「无时间记录」。
「预览上课弹窗」仍在第一层，用于手动看一眼上课弹窗的样子。

## 单实例

不允许同时开两个智慧课堂。两个坑都踩过，所以现在是三重保障：

1. **命名互斥量**（跨进程），但它在 Unix 上和"持有它的线程"绑死——线程一退就失效，
   实测出现过两个实例同时在跑，所以不能只靠它；
2. **独占锁文件** `<用户数据>/SmartClassroom/.instance.lock`（`FileShare.None`，进程级、由内核持有）
   —— 这个是主力；
3. 第二个实例给出提示后**强制 `Environment.Exit(0)`**：只调 `desktop.Shutdown()` 不行，
   第二个实例没有主窗口，Shutdown 不会真的结束进程，提示窗会一直挂在屏幕上
   （用户看到的就是"多开没被拦住"）。

提示窗**不进任务栏**（`ShowInTaskbar=false`），否则任务栏多一个图标，同样像"没拦住"。
多开会抢同一个 SnowLuma 进程、同一个 5199 桥接端口、同一份 `state.json`（后写的覆盖先写的）。

## 关闭行为与管理员密码

- **关闭主窗口默认收回到托盘**（托盘菜单可重新打开或退出）。托盘在部分 Linux 桌面环境不可用，
  此时自动退化为「关闭即退出」，不会出现关不掉的情况。设置页另有「退出应用」按钮作为第二条退出路径。
- **管理员密码**（PBKDF2-SHA256，随机盐 10 万次迭代，只存哈希不存明文）：
  设置后，改设置、切换功能开关、增删作业、处理待确认事项、以及**彻底退出**都需要验证。
  验证一次后 10 分钟内免重复输入；但**退出永远重新询问**。
  设置密码后立即生效（无需重启），且当前会话保持已解锁，不会被自己锁在外面。

## 作业过期：自动删除

作业的 `date` 语义是"**哪一天的作业**"：过了那一天就不再是"今天的作业"，所以直接删掉，
不保留历史（否则作业墙会一直堆积）。

- 清理时机：**启动时**一次 + **每 30 秒**一次（跨天不用重启）；连带 `state.json` 一起清。
- 每次清理都会在「事件」页记一条「已删除 N 条过期作业（科目…）」，不会"莫名消失"。
- 作业墙本身也再挡一道（`date < 今天` 不显示），避免清理还没跑到时闪过期卡片。
- 想要历史记录的话：作业内容在删除时会记进事件时间线，但**完整条目不再保留**。

> 注意：有卡片被挡掉时"可见卡片下标"与"存储下标"不一致，
> 拖拽排序按映射换算（`_visibleStoreIndex`），否则会挪错卡片。

## 风险确认：只在点「启动」时弹

封号风险警告**不在启动时弹**，也不在设置页占一行——那时候弹/放，用户都不知道你在警告什么。
它只出现在真正要注入的那一刻：点「启动」→ 弹出完整警告 → 确认后才继续。
确认过一次就不再问（记在 `settings.json`）。

> 注意别把两件事搞混：**封号风险**是我们自己的提示（一次性，点启动时弹）；
> **用户协议/隐私政策**是 SnowLuma 自己的（见下节，同意一次后也只在它条款变更时才再问）。

## SnowLuma 的协议同意（不完成它就不注入）

SnowLuma 启动后会停在 `awaiting EULA/PRIVACY consent before the panel unlocks`：
**同意之前它不会注入，OneBot 的 HTTP 服务也不会起来**。这时用户看到的现象是
"检测不到账号 / 已启动但未注入"，而原因是协议没同意——所以应用要自己把这件事做掉。

做法（在风险警告之后、真正启动之前）：

1. **先看 SnowLuma 自己记过没有**：读它 `config/consent.json` 里的 `version`，
   与我们按**它自己的算法**算出的当前版本（`sha256(id\0text\0 …)` 的 hex 前 16 位）比对；
   一致就说明用户已经在 WebUI 里同意过 → 直接跳过，不再问第二遍；
2. 否则读它安装目录里的 `EULA.md` / `PRIVACY.md`（正文原样，不转述），弹窗让用户读并选择；
3. 同意后用它的官方开关启动：环境变量 `SNOWLUMA_ACCEPT_EULA=1` + `SNOWLUMA_ACCEPT_PRIVACY=1`
   （**两个必须同时给**，只给一个会被它忽略；值只认 `1`/`true`）；
4. 记下这个版本号。协议文本一改版本就变，会重新征得同意。

版本算法是**逐字节复刻**它的实现，并用 node 按它源码独立算过一遍对照（两边同为 `dcb31a7b03a0b64d`），
所以能可靠地认出"它已经同意了"。

### 还要打开它的"自动注入"

SnowLuma 的 `config/runtime.json` 里 `hookAutoLoad` 默认是 **false**：
它只起 WebUI，**发现 QQ 进程也不会注入**（日志里只有 WebUI 那几行）。
所以点「启动」时应用会把这个开关打开（写回 `runtime.json`，保留其它字段，原子替换），
并在事件页记一条「已开启 SnowLuma 的自动注入」。想关掉在 WebUI 里改回去即可。

### ClassIsland 插件（应用自带，一键安装）

配套插件在 `src/ClassIslandPlugin/`，**安装包里自带一份**。它现在真的能用了 ——
之前有四个坑，全都踩过并修掉了（见本节末尾）。

- 设置页 → ClassIsland 集成 → **「安装插件」**：应用把它复制到
  `<ClassIsland 根>/Plugins/smartclassroom.bridge/`，重启 ClassIsland 后状态就会变成"已连接"；
- 也单独提供 `smartclassroom-classisland-plugin.cipx`（ClassIsland 的插件包，就是个 zip），
  可以自己在 ClassIsland 里导入；
- 找不到 ClassIsland 目录时会明确告诉你手动把 `classisland-plugin` 里的文件放到哪。

> 之前几个版本只发布了应用、**没有发布插件** —— 所以 ClassIsland 一直是"未连接"。

#### 提醒内容必须用 ClassIsland 的模板数据

给 ClassIsland 发提醒时，`MaskContent`/`OverlayContent` 的 `Content` **不能塞纯字符串** ——
那没有对应的模板，渲染出来就是"没图标、文字偏移、字号不对"。要用它的模板数据类：

- 遮罩：`TwoIconsMaskTemplateData { Text, LeftIconSource, HasRightIcon }`
- 正文：`SimpleTextTemplateData { Text }`
- 模板**必须显式给资源键**：`ContentTemplateResourceKey = "NotificationTwoIconsMaskTemplate"`
  （正文是 `"NotificationSimpleTextOverlayTemplate"`）。不给键的话它不按类型自动匹配，
  直接把数据对象 `ToString()` 出来 —— 通知里会显示一长串类型名（实测踩到）。
- 图标：`new FluentIconSource("\uF8009")`。码位要取自 **FluentAvalonia 的 `Symbol` 枚举**
  （ClassIsland 用的就是这套 Fluent System Icons 字体）；照 Segoe MDL2 猜会错位
  （实测 `E7E7` 在这套字体里是笑脸）。当前：召唤=`F8009`(AlertUrgent)、
  换课=`E15F`(arrow_swap)、手动=`E9E4`(info)，右侧统一用 `E025`(alert，Fluent 里就是铃铛；
  别用 `service_bell` —— 那个在这个尺寸下看着像餐盘盖)。

三个渠道各配了图标（召唤=铃铛、换课=提示、手动=警告），渠道属性里也带上了 `iconGlyph`。

#### 插件踩过的四个坑

1. **没发布**：打包脚本只发应用，插件一直留在源码里。
2. **SDK 太旧**：插件用 `1.7.106.2-dev-v2` 编译，而 ClassIsland 已经 2.1 ——
   提醒提供方要用官方的 `AddNotificationProvider<T>()`（`ClassIsland.Core.Extensions.Registry`）
   注册，用 `AddHostedService`/`AddSingleton` 都不行，ClassIsland 的提醒宿主找不到它
   （报"没有找到与 … 对应的提醒提供方"）。现在 SDK 跟着 ClassIsland 版本走（`2.1.0.1`）。
3. **依赖 ASP.NET**：桥接原本用 Kestrel，而 ClassIsland 是普通 .NET 应用、不带 ASP.NET 运行时 →
   `Could not load file or assembly 'Microsoft.AspNetCore'`。现在用 BCL 的 `TcpListener`
   自己处理那三个接口，零框架依赖。
4. **线程**：ClassIsland 的提醒 API 必须在 **UI 线程**调用，否则抛 `Call from invalid thread`
   （HTTP 线程直接调会得到空响应）。现在通过 `Dispatcher.UIThread.InvokeAsync` 切过去。

**实测结果**（用真实课表跑的）：

| 用例 | 结果 |
|---|---|
| `GET /status` | `{"pluginVersion":"0.35.0","classPlanLoaded":false}` |
| `POST /notify`（召唤） | `{"ok":true}` —— ClassIsland 真的弹了通知并语音播报 |
| `POST /exchange` 周一第2节语文 ↔ 第4节数学 | `legal:true`「已将09-28第2节（语文）与第4节（数学）对调。（已写入临时层课表）」 |
| `POST /exchange` 今天（周六） | `legal:false`「09-26 当天没有课表，无法自动换课」 |
| `POST /exchange` 周一第3节英语 → 自习 | `legal:true`「已将09-28第3节（英语）替换为自习」 |

> 换课会**真的写进临时层课表**（ClassIsland 里会显示调换后的课），验证完记得清掉。

#### 目录包安装（Linux）的路径

ClassIsland 的目录包安装把用户数据放在 `<应用目录>/data/`：
插件放 `data/Plugins/<id>/`，配置（含我们的 `bridge.token`）在 `data/Config/Plugins/<id>/`。
应用会自动在这些位置里找 token（「自动查找」按钮），找不到时才需要手填。

#### 启动画面卡住（ClassIsland 2.1.0.1 的问题）

实测 ClassIsland 2.1.0.1 的"正在启动…"窗口有时不会自己关（**与插件无关**，拿掉插件也一样）。
它自己有开关：`data/Settings.json` 里 `IsSplashEnabled: false` 就不再显示启动画面。

### ClassIsland 的状态与语音播报

- 「连接状态」只显示**短状态**（`已连接 · 插件 vX · 课表已加载` / `未连接`），
  排查细节（ClassIsland 是否启动、插件是否加载、端口与 token）放在**悬停提示**里，不再把状态行撑爆。
- **召唤通知不拦 ClassIsland 未连接**：连不上时降级为应用内横幅 + 系统通知，功能照用。
  但如果你装 ClassIsland 就是为了**语音播报**，那降级就没有播报了 —— 所以未连接时
  召唤那一行会明确提示：`ClassIsland 未连接：只发应用内通知，没有语音播报`。
- 「上课课件弹窗」不同：它**必须**有 ClassIsland（上课事件只能由它提供），所以那一项是硬门槛。

### provider / 模型下拉为什么是空的

那两个下拉的条目来自「载入目录」（问 sidecar 要 provider/model 列表），
而**保存的模型名不一定在列表里**（自定义 endpoint、列表没加载、sidecar 没起来）。
所以现在下拉里会用占位文本显示**当前实际生效的值**，载入目录后再自动选中同名条目 ——
不会再出现"明明能用却显示空白"。

### WebUI 的登录密码

SnowLuma 的 WebUI（`http://127.0.0.1:5099`）默认**每次启动随机生成一个初始密码**，
而且这个密码**只打印到 stdout** —— 从桌面图标启动的用户根本看不到它
（它自己的日志里只有"凭据"横幅，没有密码本身）。

应用现在用它的官方环境变量 `SNOWLUMA_WEBUI_BOOTSTRAP_PASSWORD` 替用户定一个：
点「启动」时若发现它还在用初始密码（`config/webui.json` 的 `mustChangePassword=true`），
就生成一个 12 位随机密码（避开 `0/O/1/l/I`）传给它，并显示在设置页上，带「复制密码」按钮：

> 登录 WebUI：用户名 `admin`，初始密码 `xxxxxxxxxxxx`（登录后请自行修改）

也可以**自己指定**：设置页有「设置密码…」按钮，弹窗输入即可（留空 = 改回自动生成，至少 8 位 ——
SnowLuma 自己会忽略更短的值）。

> **踩过的坑**：这个环境变量只在 SnowLuma **没有 `config/webui.json`** 时才用来播种凭据
> （它源码里 `envBootstrapPassword` 那段），文件已存在就直接忽略、沿用旧哈希 ——
> 所以"改了密码、重启了、还是密码错误"。应用现在会先把那份凭据**备份成 `webui.json.bak-*` 再删掉**，
> 让它用我们的密码重新播种，并用日志里的 `credentials seeded from ...` 确认真的生效。
> 实测：`POST /api/login` 用自己设的密码返回 `{"success":true,"mustChangePassword":false}` ✓
已经改过密码（`mustChangePassword=false`）就不再插手。想手动看/重置也可以：

```bash
cd ~/.local/share/SmartClassroom/snowluma
./launcher.sh                                    # 从终端启动：密码会打印在输出里
SNOWLUMA_WEBUI_BOOTSTRAP_PASSWORD=你的密码 ./launcher.sh   # 或者自己指定
rm config/webui.json && ./launcher.sh            # 或者删掉配置，让它重新生成一个
```

### 改了设置不用重启（热应用）

老师名单、群列表、功能开关以前都是**启动时的快照** —— 改完必须重启，
用户看到的现象是"我都把老师加进去了怎么还被当陌生人"（实测踩到）。现在：

- **老师名单**：保存后立刻重载（`TeacherMap.Reload`）；
- **功能开关**：保存后立刻更新（`PipelineService.UpdateFlags`）；
- **群列表 / 监听开关**：每条消息都读当前设置。

### 私聊也要过"老师名单"这一关

私聊走的是**独立的陌生人过滤**：老师名单非空时，**名单外的人私聊一律忽略**
（事件页会写明是哪个 QQ，并告诉你去 设置 → 老师映射 里加上它）。
所以"我私聊发了怎么没反应"通常是这两种情况之一：

1. 老师映射里没有发送者的 QQ（名单为空时不过滤，配了就会过滤）；
2. 运行时压根没在跑 —— 检查状态栏是不是"未配置：…"（0.35.6 之前，
   **只监听私聊**的配置会被误判为未配置，那样连 QQ 都不会连）。

### 谁有权触发（默认只认老师名单）

**换课会真的改课表**，所以默认开启「只处理老师名单里的消息」：名单外的人发来的
换课/作业/召唤**不自动执行**，转人工确认（事件页会记一条，待确认里能看到）。

- 判定方式：QQ 号 / 群名片 / 昵称任一命中「老师映射」即认作老师；
- 老师名单为空时不做过滤（否则刚装好什么都用不了）——所以**配好名单再开功能**；
- 想放开就关掉这个开关（设置 → QQ 连接 → 只处理老师名单里的消息）。

### 换课解析会带上真实课表

消息常常不说第几节（"明天的那个周测改成语文了"）—— 不给课表，AI 只能留空节次，
整条转人工。现在解析前会通过插件取**今天/明天**的课表一起喂给 AI：

```
今天（2026-09-27）：第1节周测
明天（2026-09-28）：第1节语文早自习、第2节语文、第3节英语、第4节数学…
```

插件新增 `GET /classplan?date=yyyy-MM-dd`，**临时层优先**（走 ClassIsland 的
`GetClassPlanByDate`，它会先查按日期覆盖的临时层，再回落到周循环课表），
返回节次、科目与起止时间，并标明这份课表是不是临时层。

实测：

| 消息 | 解析结果 |
|---|---|
| 明天的那个周测改成语文了，语文老师要讲课 | `Replace` → 09-28 第10节（数学）改为语文 |
| 周一第二节和第四节换一下 | `Swap` 第2节（语文）↔ 第4节 |

### 换课只会有"一个"临时层

同一天连做多次换课（对调 + 替换）后，仍然只有**一个** `周一（临时层）`：
写入前先看那天有没有临时层，有就**合并进去**（`OrderedSchedules` 里始终只有一条），
不会每换一次就新建一份。

### 老师通知转发（第 6 个功能）

老师发的**活动/集合/时间地点/催交**这类通知，整理成一条简短提醒，经 ClassIsland 通知学生
（上课排队、下课时发，和召唤同一套调度门）。默认**关**，需要 QQ + AI 就绪才能开。

分类里专门区分了"布置作业"和"催交作业"：

| 消息 | 判定 |
|---|---|
| 今天数学作业：练习册P10 | homework（新任务） |
| 昨天作业 12,13,14 号没有交，快点交上来 | **notice**（催交，不是新作业） |
| 今天你们下午有个活动，2:00 到大礼堂 | notice → 标题「今天下午2:00到大礼堂」 |

### 作业的截止时间有三种情况

- 提到截止 → **换算成具体日期并保留原话**：`2026-09-29（后天交）`；
- 明确说不用交/自行完成 → `无需提交`；
- **没提**截止 → 留空，卡片显示「**未说明截止**」（不瞎编）。

### 换课日期支持跨周

换课解析分两步：先让 AI 判断这条消息**涉及哪几天**（提示词里直接给了"本周一/下周一"作为基准，
"下周三"按下周一+2 算，且所有日期必须在今天之后），再按那些日期去取课表喂给 AI。

| 消息 | 解析 |
|---|---|
| 明天的那个周测改成语文了 | 09-28 → `Replace` 第10节（数学）改为语文 |
| 下周三的数学和周五的语文换一下 | 09-30 / 10-02 → `CrossDay` 第5节 ↔ 第2节 |
| 这周五第三节和下周第一节换课 | 10-02 / 09-28 → `CrossDay` 第3节 ↔ 第1节 |

### AI 在应用里做什么

| 用途 | 谁触发 | 产出 |
|---|---|---|
| **消息分类** | 每条进入监听范围的消息 | `homework / exchange / summon / none`（本地关键词只当 AI 不可用时的兜底） |
| **召唤解析** | 分类为 summon | 被叫的人、哪个老师、是否紧急、**通知标题与正文** |
| **作业整理** | 分类为 homework | 科目、日期、条目、截止说明 |
| **换课解析** | 分类为 exchange | 类型/从哪节到哪节/目标科目 → 交插件按真实课表校验 |

其余全在本地：上课排队与下课发送、谁有权触发（老师名单）、课件弹窗（按日期+科目查归档索引）、
文件归档分类、过期作业清理。

> 分类**先问 AI**：本地关键词表会把"王子诚你上来把作业发一下"错判成作业（其实是召唤），
> 所以现在关键词只在 AI 调用失败/答不上来时兜底。没命中关键词的消息也照样交给 AI
> （可用设置里的「没命中关键词也交给 AI 判断」关掉以省调用）。

### 通知的标题与正文由 AI 生成

提示词里给了例子，AI 直接产出大字标题与小字正文（例如
「王子诚你上来把作业发一下」→ 标题`请王子诚上来发作业`、正文`王子诚（信息）：王子诚你上来把作业发一下`）。
AI 没给（或旧格式）时回落到本地模板；同名时本地模板也不会写成"王子诚请王子诚过去"。

### 归档目录里只有文件

元数据（发送时间/群号/发送者/科目）写在 `<归档根>/.smartclassroom-meta/<科目>/<文件>.json`，
**科目文件夹里只有真正的文件**（以前会生成一堆同名 `.meta.json`，看着像垃圾）。
旧的 `.meta.json` 仍会被读取（去重与课件索引不受影响），可以手动删掉。

### 上课课件弹窗（同一天 + 同一科目）

ClassIsland 报"上课了" → 应用按 **当天日期 + 本节课科目** 从归档索引里找课件：

- 科目未知的文件只有确认是**这位老师**的才放行（同一位老师一般只有一门课，误弹概率低）；
- 一节课只弹一次（同一科目同一天去重）；
- 没有当天该科的课件就**不弹**；
- 弹窗标题就是「您可能需要的课件」，设置页有手动测试按钮。

### 私聊文件也能归档

SnowLuma 把**私聊文件**转成"**带 file 段的消息**"（不是 `notice.group_upload`），
段里直接给了下载直链。应用现在两种都认：

- 私聊文件：用段里的 `url` 直接下载；
- 群文件：段里没 url 时再调 `get_group_file_url`；
- 事件页里会**像显示消息内容一样显示文件名**（`cherenkov_animation.html（7.1MB）`），
  归档完变成 `已执行：已归档`。

### 事件页：一条消息 = 一条记录，实时显示处理进度

每条消息在事件页**只占一条记录**，先在"进行中"状态（转圈 + `处理中 1.2s`），
把过程中的每一步写在它下面：

```
收到群消息 · 正在处理 3.4s
王子诚：王子诚你上来把作业发一下
   → 交给 AI 分类…
   → AI 判定为 召唤 · 正在处理…
   → AI 请求失败（第 1/3 次）：…401 Invalid API key…（检查 API Key…） · 1 秒后重试
   → 正在重试（第 2/3 次）…
```

处理完**就地**变成结果行，措辞只有三种：

- **已忽略**（与三个功能无关 / 发送者不在老师名单 / 该群没有监听 / 换课非法转人工）
- **已执行**：召唤（立刻/排队）、作业已上墙、换课
- **出现错误**：AI 失败、解析失败等

没监听的群也会给一条"已忽略（该群没有监听）"，但**每个群只提示一次**（几十个群不会刷屏）。

**AI 失败会重试**：最多 3 次（1s / 3s 退避），每次失败与重试都实时写在进度下面 ——
端点抽风（opencode-go 实测有一次挂了 76 秒）不再是"卡住没反应"。

### 召唤通知里会写清"哪个老师、哪一科"

群里常只说"老师叫你过去一趟"，光凭这句话谁也判断不出是谁。现在解析时会带上上下文：

- 发送者是谁（是否在老师名单里、教什么）；
- **当前课程的科目与科任老师**（来自 ClassIsland 的当前课程）；
- 班里已知老师的名单（用于把"数学老师"匹配到具体的人）。

AI 据此把"老师"落到具体的人，通知就变成「张老师（数学）请小明过去」，
而不是含糊的「老师请小明过去」。

### 监听哪些群

默认**只监听你列出的群**，而不是该账号所在的全部群 —— 这是刻意的：班级号往往在几十个群里
（实测那个号有 43 个群，包括各种技术群），全监听会让它在无关群里也触发 AI 与通知，
既费钱又会产生莫名其妙的作业/换课。

- **「选择群…」**：从 OneBot 拉该账号的群列表（带群名与人数），**复选框多选**，不用手打群号；
  （早先用的是多选 ListBox —— Avalonia 的多选要按 Ctrl 点，看起来就像只能单选，所以换掉了）
- **「监听老师私聊」**：老师私聊发的「来一下」/作业也处理；只认老师映射里的 QQ，
  陌生人私聊一律忽略（名单为空时不做过滤）。**只监听私聊是合法配置** ——
  不选群也能开功能（那种情况下群消息一律不处理）；
- 也可以直接在输入框里手填（英文逗号分隔）；
- **「监听全部群」**开关：确实想全监听时打开（会在事件页记一条警告）。

一个坑：**群列表属于"抢到 OneBot 端口的那个账号"**。多账号时如果班级号没抢到 3000/3001，
你看到的群列表就是另一个号的（实测：另一个号只有 6 个群，班级号有 43 个）。

解决办法：设置页多账号提示旁边的 **「自动分配端口」** —— 应用会给每个账号写一组互不冲突的端口
（第一个 3000/3001、第二个 3010/3011…，改的是它自己的 `config/onebot_<uin>.json`，保留其它字段），
然后重启 SnowLuma 生效。之后**选了哪个账号就自动填哪个账号的地址与 token**，
不需要再关心端口是谁的。

### OneBot 要带 token（应用会自动读）

SnowLuma 的 OneBot HTTP/WS **默认要求鉴权**：不带 token 的请求一律
`{"status":"failed","retcode":1401,"wording":"unauthorized"}` ——
表现就是应用"检测不到账号 / 看不到在线"。

token 就写在它的配置里：`config/onebot_<uin>.json` → `networks.httpServers[0].accessToken`
（43 位随机串，每个账号一份）。

> ⚠️ **HTTP 与 WS 是两个不同的 token**：`httpServers[0].accessToken` 与
> `wsServers[0].accessToken` 各一个（实测不同）。只填 HTTP 那个时，HTTP 调用能通、
> **WS 升级会被拒 401**（SnowLuma 日志：`rejected unauthorized WebSocket upgrade`），
> 表现是应用一直"QQ 未连接（重连中…）"、**消息事件一条都收不到**。
> 应用点「检测并选择账号」会把两个 token 都填上（设置页有单独一行「OneBot WS Token」）。
> 另外**地址与 token 必须是同一个账号的**：手工把 URL 改成另一个账号的端口、token 没跟着换，
> 就会出现"HTTP 能通、WS 一直 401"（实测踩到）。应用启动时会校验这组组合，
> 不对就按 SnowLuma 的配置自动纠正，并在事件页说明。应用会**自己读出来**（地址、端口、token 一起），
并逐个账号试到能应答为止——**3000/3001 归哪个账号取决于 SnowLuma 启动时谁先登录**，
所以不能假定是哪一个，也不能让用户手抄 token。

> 另外踩过一个坑：动作调用（`get_login_info` 等）走的是反序列化，而 OneBot 返回的是
> snake_case 的 `user_id`；模型里少写 `JsonPropertyName` 就会永远读到 0，
> 于是"明明在线却检测不到账号"。事件那条路是 `OneBotParser` 手写读取，不受影响。

### 多账号：3000/3001 只能给一个号

SnowLuma 会给**每个登录的 QQ** 都开一套 OneBot 适配器，而默认端口都是 3000/3001。
于是第二个登录的账号必然 `EADDRINUSE`（`network startup degraded: failures=2`），
它就没有 OneBot 服务可用了 —— 这就是"两个号都登着，只有一个能连上"的原因。

应用现在会从 SnowLuma 的日志里读出**登录过哪些号**（`session started: UIN=`），
多于一个时给出提示，并把这些号都放进「检测并选择账号」的候选里
（不只是当前占着端口的那一个）。日志里那几类 DEBUG 行（`Event0x210 unknown subType=381/382`、
`login history sync disabled`）是无害噪音，不用管。

想两个号都接入，就在 SnowLuma 的 WebUI 里给每个账号分配不同端口；
否则建议只保留班级 QQ 登录。

### Linux 上注入的两个关卡

**第一关：ptrace 权限。**

SnowLuma 的注入是"跟踪一个已经在跑的 QQ 进程"，而 Arch 默认
`kernel.yama.ptrace_scope=1`（只允许跟踪**自己的子进程**）→ 注入必然失败，
它自己的日志里只有一行 `[Hook] load failed ... COMPONENT_LOAD_FAILED`。

```bash
sudo sysctl kernel.yama.ptrace_scope=0      # 临时放开（重启失效）
# 永久：/etc/sysctl.d/99-snowluma.conf 里写 kernel.yama.ptrace_scope=0
```

**第二关：注入组件在 QQ 进程内加载失败**（`COMPONENT_LOAD_FAILED`）。
过了 ptrace 这一关之后，如果日志变成这一条，说明**附加已经成功**、失败发生在把注入组件
加载进 QQ 的时候 —— 这属于 SnowLuma 原生注入与具体 QQ 版本的兼容性问题，不是本应用能修的。
界面上会连同**本机 QQ 版本**一起显示出来，便于对照 SnowLuma 支持的版本、或改用它的 Docker 部署。

两种情况应用都会**读 SnowLuma 的日志**把原因直接显示在「运行状态」下面（不用翻日志），
设置页另有「打开日志」按钮直达它的日志目录。

### 接管已在运行的实例

「启动」时若发现 SnowLuma 已经在跑（上次应用启动的、或用户手动启动的），
**直接接管而不是再开一个**：两个实例会抢同一个 WebUI 端口（第二个会自动换到 5100，
于是应用里显示的地址指向另一个实例），而且「停止」会停不掉真正在跑的那个。
接管后「停止」也能把它停掉（按 pid 杀进程树）。

### 不重定向它的输出

SnowLuma 会同时写自己的日志文件和 stdout。应用**不再接管它的 stdout/stderr**：
一旦应用退出，管道就断了，而它会陷入"写管道 EPIPE → 记一条错误日志 → 又写管道"的死循环
（实测把它自己的日志刷到 291MB）。要看它的输出请用设置页的「打开日志」。

为什么不用它的 HTTP 接口：`/api/agreements` 与 `/api/agreements/record-consent` 虽然存在，
但**需要先登录 WebUI**（未登录返回 401），而首次的初始密码是它每次启动随机生成、只打印在
进程输出里。抓日志里的密码太脆，环境变量是它留给自动化的正路。

> 应用**不会**替用户同意：不同意就返回、不启动，并在界面上写明"未同意协议"。

## 作业卡片

WinUI3 风格卡片：左侧按科目稳定取色的色条、相对日期（今天/明天/还有 N 天）、条目列表、
来源与条数。**按住卡片左侧手柄可拖动排序**，顺序随 `state.json` 一起持久化。

## 作业页布局

**响应式卡片网格**：卡片固定宽度 344，由 `WrapPanel` 按窗口宽度自动换行成多列，
窗口拉伸时列数跟着变（不是单列列表）。条目显示为 `1. 2. 3.` 编号。
拖动左侧手柄可重排——命中判断按**卡片实际矩形**做（X+Y），而不是只看 Y，
否则多列网格里会把不同列的卡片串在一起。

## 界面与字体缩放

设置页「外观 → 界面与字体缩放」提供 80%~160% 滑块，改完立即生效、随设置持久化。
实现方式是 `LayoutTransformControl` 整体缩放：字号、图标、卡片一起放大，
**保住了主题原本的字号层级**（标题/正文/说明的相对大小），
比逐个覆盖 FontSize 更不容易把界面搞乱；卡片网格也会随缩放重新排列。

## 作业卡片拖拽（长按）

**长按卡片约 0.3 秒**进入拖拽。拖拽期间：

- 只有一张跟随指针的**"虚"卡片**（原始卡片压暗到 30%，不做缩放——缩放会溢出格子边界）；
- **目标位置用虚线边框指示**，框住将要落位的格子；
- **列表本身完全不动**，松手才真正落位（`MoveItemLive` 只调用一次）。

这样既没有卡片乱跳，也不需要在拖拽中反复改集合——而这正是之前丢指针捕获、甚至崩溃的根源。

**布局：瀑布流（`MasonryPanel`）**，不是 WrapPanel。WrapPanel 有两个浪费：

1. **右侧留白**——卡片固定宽度，塞不下下一列就空着；
2. **同行等高**——同一行里最高的卡片会把矮卡片撑高，下面留一大片空白。

瀑布流面板按可用宽度算列数、**卡片宽度拉伸填满整行**，并且**每列独立向下堆叠**，
矮卡片不会被旁边的超高卡片撑高。列数上限默认 4，可用宽度放不下时退化为单列。

**多行落位判定**用矩形命中（X+Y），不是只比 Y；落在行列间隙时回退到中心点最近的格子
（等距时取靠前的，保证稳定不抖动）。

注：Avalonia 会把子元素 Bounds 取整到整像素，所以边缘会有约 1px 的舍入差——
精确断言放在 `MasonryLayout` 的纯数学测试里，面板级测试用 1px 容差。

两个已修的坑（都会让拖拽表现异常）：

1. `PointerMoved` 在**只悬停不按键**时也会触发。若只判断"是否在拖拽中"而不检查左键是否仍按住，
   松手后会继续跟着鼠标重排 —— 现在每次移动都确认左键状态，一旦松开立即结束拖拽。
2. 拖拽中若调用 `Refresh()`（Clear + 重建卡片），**正在拖动的那张控件会被从可视树摘掉**，
   指针捕获随之失效、松手事件收不到，就会一直粘着鼠标。现在拖拽走 `MoveItemLive()`
   （只做 `ObservableCollection.Move`，复用现有控件），并在拖拽期间挂起定时刷新。

## 刷新的坑（拖拽失效 + 崩溃的根因）

主窗口有个 2 秒定时刷新。原实现每次 `Refresh()` 都 `Clear()` + 重建全部卡片，
于是**按住准备长按时卡片控件被销毁，指针捕获丢失 → 拖拽失效**；
在指针事件派发过程中销毁控件还可能**直接崩溃**。

现在三道防线：

1. **数据没变就不重建**（按内容+顺序算指纹），定时刷新绝大多数时候是空操作；
2. **从"按下"那一刻起挂起刷新**（不只是拖拽中），松手后强制补一次刷新；
3. **UI 事件全部 try/catch + 全局未处理异常拦截**（`Dispatcher.UIThread.UnhandledException`
   记入事件流且不退出进程），界面层异常不再能崩掉整个应用。

## 缩放范围

Ctrl+滚轮 / 设置页「外观 → 作业内容缩放」**只缩放「作业」页的卡片区**（80%~180%），
不影响导航栏、设置页等其余界面。

## AI 返回空内容怎么办

界面上曾出现「可用，但返回为空」——**这不是"连通但没用"，而是一个被当成成功的错误**。
常见原因与现在的处理：

| 现象 | 原因 | 现在的行为 |
|---|---|---|
| `finish_reason=length` | 输出被长度上限截断 | 报错并说明是截断 |
| 只有 `reasoning_content` / `thinking` 块 | **推理模型把输出全用在思考上**，正文为空 | 报错并指出"只有思考内容（N 字）" |
| `refusal` / 只有 `tool_calls` | 模型拒答或只回工具调用 | 分别指出 |

根因修复：pi-ai 引擎改用 `completeSimple` 并默认传 **`reasoning: 'minimal'`**（设置页可调
minimal/low/medium/high）。我们的任务是"把群消息整理成 JSON"，长思考既慢又贵，
还容易把输出用光导致正文为空。该等级在自定义端点上也会以 `reasoning_effort` 发出；
若端点不认这个参数，边车会自动退回默认参数重试一次。

空内容**不再被当成成功**：内置直连与 pi-ai 边车都会抛出带原因的异常，
上层据此走保守降级（召唤排队、作业/换课转人工），而不是把空字符串当有效结果继续处理。

失败时的报错顺序也有讲究：pi-ai 把"请求本身失败"（401/404/400/网络）记在 `errorMessage` 里，
只有真的"请求成功但没正文"才是空内容。所以边车现在**先报真实失败原因**
（例如 `AI 请求失败：400: {"type":"MissingSessionID",...}（该端点要求 x-opencode-session 路由头）`），
只有拿不到失败原因时才去猜"是不是推理模型把输出用光了"。

## 作业日期不可信时按今天算

模型偶尔会吐出与自己训练数据同期的日期（实测遇到过 3 个月前的日期），
那会把作业挂到完全错误的一天。所以解析出的日期只接受 **[今天-1, 今天+14]**，
超出的一律按"今天的作业"处理，并在事件页记一条「作业日期已纠偏：… → …」。
（这里的 `date` 语义是"哪一天的作业"，截止说明在 `due` 字段里，不受影响。）

## 文件归档到哪了

目录结构：**`<归档根目录>/<科目名>/<文件名>`**（只到科目一层，不再按日期分层）。

- 科目取自教师映射；**没配科目**时退化为老师姓名；**都不认识**则归入 `未分类`。
- 归档根目录在 **设置 → 文件归档 → 归档目录** 里设置（带「浏览…」文件夹选择器与「打开」按钮）。
  留空则用默认位置，界面上会把**实际生效的路径**显示出来，不会让你找不到文件。
- 默认**只下载教师映射命中的发送者**；打开「下载群里所有人的文件」后，其他人发的也会下载（进对应科目或「未分类」）。
- 每个文件旁边有一个 `<文件名>.meta.json`，记录群号、发送者 QQ/姓名、**科目**、**发送时间**、文件 id 与原始大小。
  上课弹窗就是靠 meta 里的科目判断"当科"的。
  因为目录不再按日期分层，**发送时间要看 meta.json 或文件修改时间**；
  不同天的同名文件会得到 `(1)`、`(2)` 后缀。
- 同一个 `file_id` 不会重复下载；重名自动加序号。

| 服务地址 | 留空时用所选 provider 的官方端点；填了则按自定义 OpenAI 兼容端点处理。opencode.ai 需要的 `x-opencode-session` 路由头由程序自动补 |
| API Key | 调用 AI 服务的密钥，明文存在本机设置里（单机教室机场景，见"安全"一节） |
| provider / 模型 | 从 pi-ai 的模型目录拉取（含上下文长度与能力标记） |
| 推理强度 | 默认 `minimal`。调高会让推理模型把输出花在思考上，可能出现"只有思考、正文为空" |
| 连通性测试 | 用当前配置发一条最小请求，验证地址 / Key / 模型是否可用 |

### 文件归档

- 目录结构：**`<归档根目录>/<科目名>/<文件名>`**（只到科目一层）。
  科目取自教师映射；没配科目时用老师姓名；都不认识则归入「未分类」。
- 每个文件旁有 `<文件名>.meta.json`，记录群号、发送者、科目、发送时间、文件 id 与大小。
- 同一 `file_id` 不重复下载；重名自动加 `(1)`、`(2)`。

### ClassIsland 集成

- **桥接端口**：插件在本机监听的端口，需与插件设置一致（默认 5199）。
- **桥接 Token**：插件首次启动时生成，可用「自动查找」从 ClassIsland 配置目录取出并填入。
- **连接状态**：探测插件是否已加载并在线；课表未加载时仍算"已连接"但会给出提醒。

### QQ 连接

- **SnowLuma 下载器**：注入层不随应用附带。完整版内置 Node，精简版需自备 Node ≥ 22。
- **风险确认**：点「启动」时先弹封号风险警告，确认后**紧接着弹 SnowLuma 的用户协议与隐私政策**
  （见下节），两个都过了才开始注入；已确认风险后可「重新查看」。
- **运行状态**：`已注入，在线` / `已注入，但 QQ 未登录` / `已启动，未注入` / `未启动（未注入）` /
  `QQ 未运行` / `未安装 SnowLuma`。**没有单独的「探测」按钮**——点「启动」「停止」会自动探测，
  「检测并选择账号」也会顺带刷新状态。状态一直停在"已启动，未注入"时，多半是协议没同意
  或 `hookAutoLoad` 没开（这两件事应用现在都会自动处理，过程记在事件页）。
- **班级 QQ 账号**：同一台电脑登录过多个 QQ 时，用「检测并选择账号」指定要注入的那个；
  候选来自当前在线账号与以前选过的账号，也可手动输入。检测不到时会在下面直接写明卡在哪一步
  （没装 / QQ 没运行 / SnowLuma 没启动 / 没同意协议 / 端口或 Token 不一致）。
  探测到在线账号与所选不一致会提醒。
- **OneBot Token**：OneBot 端配了 access token 时必须与之一致，否则连不上。
- **开机自启**：随系统登录自动启动 SnowLuma。

### 安全与关闭行为

- **管理员密码**：设置后，改设置、处理待确认、彻底退出都需要验证；验证一次后 10 分钟内免重复输入，
  但**退出永远重新询问**。密码用 PBKDF2-SHA256（随机盐 10 万次迭代）只存哈希。
- **关闭主窗口收起到托盘**：托盘不可用的桌面环境会自动退化为"关闭即退出"。

## 软件更新

设置页「软件更新」会去 GitHub 查最新 tag / Release（`Galaxy1108/smartclassroom`），
比较当前版本（来自 csproj 的 `<Version>`）后给出**三态徽标**：已是最新（对钩）/
发现新版本（感叹号）/ 检查失败（叉）。Release 说明不在界面里堆一大段（那是原始 Markdown，
又长又难读），要看细节点「打开 Releases 页」。

**平台差异（重要）**：

| 平台 | 行为 |
|---|---|
| Windows | 「下载并安装」可用：下载 `win-x64.zip` → 解压到 `<应用目录>/update/<版本>` → 生成 `apply-update.cmd`。关闭应用后运行它即可覆盖文件并重启（正在运行的 exe 不能被覆盖，所以必须这样绕一下） |
| Linux | **明确禁用**自动替换：界面只写一句「Linux 平台暂不支持应用内自动更新」，只保留「打开 Releases 页」。应用装在 `/opt` 并由 pacman 管理，自己换文件会让包数据库与实际文件不一致，更新走包管理器（`sudo pacman -U 新版 .pkg.tar.zst`） |

发版流程（让更新功能真正可用）：

```bash
# 1. 改版本号（两处要一致）
#    src/App/SmartClassroom.App.csproj 的 <Version>
#    pkg/PKGBUILD 的 pkgver
bash pkg/build-linux.sh && bash pkg/build-windows.sh
git commit -am "release: v0.23.0" && git tag v0.23.0 && git push --tags
gh release create v0.23.0 pkg/smartclassroom-0.23.0-*.pkg.tar.zst pkg/smartclassroom-0.23.0-win-x64.zip \
  --title "v0.23.0" --notes "更新说明…"
```

Windows 自更新要求 Release 里带上 `…-win-x64.zip` 资产；没有资产时按钮会置灰并说明原因。

## 调试设置

设置页最下方有「调试」区，目前只有一项：

- **清空所有设置**：确认后把 `settings.json` 恢复默认（AI / QQ / 归档 / 教师映射 / 功能开关 /
  管理员密码），并把**内存里那份也一起复位**——设置页与 Runtime 共用同一个设置对象，
  只删文件的话退出时又会被写回来。作业、待处理与事件时间线属于数据，不在"设置"范围内，不会被动。
