# 「事件」页

「事件」页是应用的**决策日志**：每条收到的消息都在这里留下一条记录，
说明它被怎么处理、为什么这么处理、花了多久。排查"消息怎么没反应"时先看这里。

## 一条消息 = 一条记录

消息进来时先建一条"进行中"的记录（转圈 + 实时秒数），处理过程中的每一步都写在它下面：

```
收到群消息 · 处理中 3.4s
张老师：张三你上来把作业发一下
   → 交给 AI 分类…
   → AI 判定为 summon · 正在处理…
   → （失败时）AI 请求失败（第 1/3 次）：…401 Invalid API key… · 1 秒后重试
```

处理完**就地**变成结果行，不会另起一条。

## 三种结果

| 结果 | 何时出现 |
|---|---|
| **已忽略** | 与功能无关 / 发送者不在老师名单 / 该群没有监听 / AI 判定不是该功能 / 换课非法转人工 |
| **已执行** | 召唤（立刻或排队）、作业已上墙、换课、通知已转发、文件已归档 |
| **出现错误** | AI 失败、解析失败、归档失败、处理异常 |

同一件事不会既"已忽略"又另起一条提示 —— 例如"该群没有监听"就是那条消息的结果本身。

## 判定来源与耗时

结果行会写清是谁判的、花了多久：

```
已忽略（与三个功能都无关）
行 我先搞一版出来 · AI 判定为 none · 耗时 3.9s
```

| 判定来源 | 含义 |
|---|---|
| `AI 判定为 X` | 正常路径 |
| `本地判定（已关闭「由 AI 判定老师消息」）` | 设置里关掉了 AI 分类 |
| `本地判定（消息太短，没花 AI 调用）` | 少于 4 个字符 |
| `本地判定（AI 没给出结论）` | 调用失败或格式不对，回退关键词 |

耗时是实际处理时间。**行首的时间是消息到达时间**，不是完成时间 ——
所以"看起来很快"不代表没走 AI，要看"耗时"。

## 待处理

AI 没能处理的消息（解析失败、类型未知、缺节次、发送者不在名单）会进入**待处理**区，
每条提供三个出口：

| 操作 | 说明 |
|---|---|
| 重新解析 | 拿原文再跑一次 AI，成功则移出待处理 |
| 手动录入 | 填表补全（作业：科目/条目/日期；换课：类型/日期/节次） |
| 忽略 | 记一条灰色的"已忽略"并移出 |

进入待处理的同时，会在**下课时**通过 ClassIsland 发一条"需要人工介入"的提醒。

## 时间线的配色

| 级别 | 颜色 | 典型内容 |
|---|---|---|
| 已忽略 | 灰 | 什么都没发生，不抢眼也不报警 |
| 信息 | 蓝 | 状态变化、恢复 |
| 成功 | 绿 | 已执行 |
| 警告 | 橙 | 转人工、QQ 端接收失败 |
| 错误 | 红 | 出现错误 |

配色定义在应用主题里，跟随系统浅色/深色切换。

## 操作

| 操作 | 说明 |
|---|---|
| 单条「复制」 | 复制该条记录（时间、标题、细节） |
| 顶部「复制全部」 | 复制整条时间线，便于反馈问题 |
| 顶部「清空」 | 清空时间线（作业与待处理数据不动） |

时间线保留最近 **200** 条，跨重启保留；启动时会把上次异常退出遗留的"进行中"记录
收尾成"已中断"，不会留下永远转圈的卡片。
