# 「事件」页

> 一条消息 = 一条记录：判定来源、耗时、三种结果、时间线配色与复制。

## 「事件」页是什么

两条用途：

1. **待处理（有出口）**——AI 失败或返回非法时，**群消息不会被丢掉**：原文、发送者、失败原因都留在待处理区，
   可以「重新解析 / 手动录入 / 忽略」。手动录入的作业直接上墙；手动录入的换课**仍走插件合法性校验**，
   不会绕过校验直接改课表。输入非法（如作业科目为空）时不会消费掉这条记录。
2. **决策时间线**——记录应用对每条群消息做了什么、为什么没做（召唤为何排队、AI 判定非召唤、换课是否被驳回、
   QQ 断线重连、课件弹窗失败、崩溃等）。这是排查"老师说了话但没反应"的第一现场。

时间线**跨重启保留**（和作业、待处理一起写进 `state.json`，保留最近 200 条），因此不会自己消失；
要清掉用时间线右上角的「清空」。前 200 条以外的旧记录会被自动挤掉，也不适合当日志长期留档。

### 时间线的配色与复制

每条记录带**严重级别**，界面按级别着色（配色定义在 `App.axaml` 的主题字典里，浅色/深色各一套）：

| 级别 | 颜色 | 什么时候出现 |
|---|---|---|
| 信息 | 蓝 | 正常流程、状态恢复、AI 判定后按预期跳过 |
| 成功 | 绿 | 已归档 / 已上墙 / 已发通知 / 换课已执行 |
| 警告 | 橙 | 功能未启用、QQ 断线重连中、换课非法转人工、AI 降级、大文件待确认 |
| 错误 | 红 | 异常（崩溃兜底）、归档失败、解析失败、提交失败 |

复制有两条路：每行右侧的「复制」按钮复制单条（`[时间] [级别] 来源 · 标题` + 缩进明细），
右上角「复制全部」导出整段（带头部与条数）。正文同时是可选中的文本（`SelectableTextBlock`），
可以像普通文档一样拖选复制；刷新做了指纹比较（数据没变不重建行），所以拖选不会被 2 秒定时刷新打断。

崩溃日志会**把 `AggregateException` 拆开**：外层那句"有任务的异常没人观察"没有任何信息量，
现在直接显示真正的内层异常与第一条栈帧（例如托盘 D-Bus 注册失败的
`org.freedesktop.DBus.Error.ServiceUnknown`）。

### 事件页：一条消息 = 一条记录，实时显示处理进度

每条消息在事件页**只占一条记录**，先在"进行中"状态（转圈 + `处理中 1.2s`），
把过程中的每一步写在它下面：

```
收到群消息 · 正在处理 3.4s
王子诚：王子诚你上来把作业发一下
   → 交给 AI 分类…
   → AI 判定为 召唤 · 正在处理…
   → AI 请求失败（第 1/3 次）：…401 Invalid API key…（检查 API Key…） · 1 秒后重试
   → 正在重试（第 2/3 次）…
```

处理完**就地**变成结果行，措辞只有三种：

- **已忽略**（与三个功能无关 / 发送者不在老师名单 / 该群没有监听 / 换课非法转人工）
- **已执行**：召唤（立刻/排队）、作业已上墙、换课
- **出现错误**：AI 失败、解析失败等

没监听的群也会给一条"已忽略（该群没有监听）"，但**每个群只提示一次**（几十个群不会刷屏）。

**AI 失败会重试**：最多 3 次（1s / 3s 退避），每次失败与重试都实时写在进度下面 ——
端点抽风（opencode-go 实测有一次挂了 76 秒）不再是"卡住没反应"。
