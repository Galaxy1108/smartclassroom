# AI 引擎与提示词

智慧课堂的"理解"全部由 AI 完成：判断一条 QQ 消息是召唤、作业、换课还是通知，
再把内容整理成结构化数据。本文说明引擎如何选择与配置、每个角色发给模型的输出契约、
图片怎么交给模型、失败如何重试，以及出问题时怎么排查。

## 引擎选择

应用内置两种引擎，在设置里二选一：

| 引擎 | 说明 | 依赖 |
|---|---|---|
| `pi-ai`（默认） | 应用自带 Node 边车（`tools/ai-sidecar/sidecar.mjs`），stdio JSONL 通信，内置各服务商与模型清单 | Node ≥ 22.19（随包附带） |
| OpenAI 兼容端点 | 直接 `POST {baseUrl}/chat/completions`，零额外依赖 | 无 |

两种引擎走同一个 `IAiClient` 接口，上层（分类、解析）不关心用的是哪个。
边车崩溃会自动重启，任何失败都转成 `AiException`，由上层按"保守降级"处理。

## 配置

设置 → **AI**：

| 项 | 说明 |
|---|---|
| 引擎 | `pi-ai` 或 OpenAI 兼容端点 |
| 服务商 | pi-ai 引擎下从边车拉取（如 `opencode-go`） |
| 模型 | 选定服务商后从边车拉取（如 `deepseek-v4.1-flash`） |
| 服务地址 | 仅"OpenAI 兼容端点"需要，形如 `https://host/v1` |
| API Key | 两种引擎都需要 |
| 推理强度 | `minimal` / `low` / `medium` / `high`，默认 `minimal` |

**关于推理强度**：分类这类任务用 `minimal` 就够（实测每次 2–5 秒、准确率足够）。
调高会明显变慢，而且部分推理模型会把输出全花在思考上、最终文本为空 ——
边车对空响应有兜底，但更慢是必然的。建议只在结构化解析频繁出错时才考虑调高。

**Key 存在哪**：设置存在 `<数据目录>/settings.json`，与程序文件分开，
覆盖安装/更新不会丢配置。

## AI 在流程中的位置

```
QQ 消息
  └─ 分类（AnalyzeKindAsync）→ homework | exchange | summon | notice | none
       ├─ summon   → 解析召唤 → 生成标题/正文 → ClassIsland 通知
       ├─ homework → 整理作业 → 作业卡片
       ├─ exchange → 判断涉及日期 → 取课表 → 解析换课 → 校验 → 临时层
       ├─ notice   → 整理通知 → ClassIsland 提醒
       └─ none     → 记一条"已忽略"
```

分类是必经的一步：它决定后面走哪条解析链。分类失败会回退本地关键词，
并在事件行里写明"本地判定"。

## 各角色的输出契约

所有提示词都要求**只输出 JSON**；解析前先抽取 JSON 片段，容错模型多说的客套话。

### 分类

```json
{"category": "homework|exchange|summon|notice|none"}
```

判定要点（提示词中以正反例写明）：

| 类别 | 判定 |
|---|---|
| `summon` | 要求（某）人过去/上来/去某处。出现"作业"但重点是"人过去"也算（"张三你上来把作业发一下"）；**没点名也算**（"你们几个过来一下"） |
| `homework` | 老师**布置新任务**；催交/点名/检查不算（"12、13、14 号没交，快点交上来" → notice） |
| `notice` | 老师向全班说一件事：活动、集合、催交、提醒、表扬祝贺、公布名次 |
| `none` | 闲聊、提问、与全班无关 |

### 召唤

```json
{"is_summon": true, "target": "被叫的人名（没点名则空）", "teacher": "叫人的老师（可空）",
 "urgent": false, "title": "通知标题", "body": "通知正文", "confidence": 0.9}
```

- `urgent` 仅在出现"现在/立刻/马上/赶紧"等词时为 `true` → 立即发送；
  否则上课时排队、下课时发；
- `title` / `body` 由 AI 生成；`target` 为空时用"你们/大家"这类泛指；
- 提示词会带上**上下文**：发送者、当前课程与科任老师、班级已知老师名单，
  用于把"数学老师"这类称呼对应到具体的人。

### 作业

```json
{"is_homework": true, "subject": "科目", "date": "yyyy-MM-dd",
 "items": ["条目1", "条目2"], "due": "截止说明", "confidence": 0.9}
```

`due` 有三种情况：

| 消息里 | `due` |
|---|---|
| 提到截止（"后天交"） | 换算成具体日期并保留原话：`2026-09-29（后天交）` |
| 明确说不用交 | `无需提交` |
| 没提 | 空字符串（卡片不显示截止那一行） |

日期会做**纠偏**：模型给出的日期与今天相差过大时按今天处理，避免作业挂到错误的一天。

### 换课

```json
{"is_exchange": true, "kind": "Swap|Replace|CrossDay",
 "from": {"date": "yyyy-MM-dd", "period": 2, "subject": "原科目"},
 "to": {"date": "yyyy-MM-dd", "period": 4},
 "new_subject": "Replace 的目标科目", "confidence": 0.9}
```

换课分两步，因为消息常常不说第几节：

1. **判断涉及哪几天**（`ResolveExchangeDatesAsync`）：提示词直接给出"本周一/下周一"作为基准
   （"下周三 = 下周一 + 2 天"），并要求所有日期必须在今天之后；
2. **取那几天的课表**（插件 `GET /classplan`，临时层优先），连同消息一起交给模型，
   让它把"周测改成语文"落到具体节次。

实测：

| 消息 | 解析结果 |
|---|---|
| 明天的那个周测改成语文了 | 09-28 → `Replace` 第 10 节（数学）改为语文 |
| 下周三的数学和周五的语文换一下 | 09-30 / 10-02 → `CrossDay` |
| 这周五第三节和下周第一节换课 | 10-02 / 09-28 → `CrossDay` |

### 通知

```json
{"is_notice": true, "title": "标题（≤14 字）", "body": "正文"}
```

只要老师是在向全班说一件事就算通知；闲聊/提问返回 `is_notice: false`。

## 图片（视觉解析）

老师发的作业/通知**截图**很常见，所以图片会真正交给模型：

1. 解析 QQ 消息里的 `image` 段，拿到直链；
2. 下载图片（单张 ≤ 4MB、一条消息最多 3 张、失败跳过）；
3. 以内容数组发送：pi-ai 用 `{type:"image", data:<base64>, mimeType}`，
   OpenAI 兼容端点用 `{type:"image_url", image_url:{url:"data:…;base64,…"}}`；
4. 正文只有 `[图片]` 占位符时，额外告诉模型"本条消息带图片，请结合图片里的内容判断"
   —— 不加这句，模型会把纯占位符判成"无关"，后面的解析根本不会跑。

因此**纯截图也能被解析成作业**：一张写着"今日作业 / 1. 数学：练习册 P10"的截图，
正文只有 `[图片]`，仍能被识别为作业并提取出科目、条目与截止时间。

> 前提：所选模型支持图片输入。纯文本模型会忽略图片内容。

## 判定来源与耗时

事件页每条结果行都会写清是谁判的、花了多久：

```
已忽略（与三个功能都无关）
行 我先搞一版出来 · AI 判定为 none · 耗时 3.9s
```

| 判定来源 | 含义 |
|---|---|
| `AI 判定为 X` | 正常路径 |
| `本地判定（已关闭「由 AI 判定老师消息」）` | 设置里关掉了 AI 分类 |
| `本地判定（消息太短，没花 AI 调用）` | 少于 4 个字符 |
| `本地判定（AI 没给出结论）` | 调用失败或返回格式不对，回退关键词 |

耗时是**实际处理时间**；行首的时间是消息到达时间，不是完成时间。
走 AI 通常至少一两秒，几百毫秒说明走的是本地判定。

## 失败、重试与降级

| 情况 | 处理 |
|---|---|
| 单次调用失败 | 最多尝试 3 次，间隔 1s / 3s / 5s，过程实时写进那条消息的进度 |
| 三次都失败（分类） | 回退本地关键词，事件行写明"本地判定" |
| 三次都失败（解析） | 进入**待处理**转人工，并在下课时通过 ClassIsland 提醒 |
| 单条消息抛异常 | 只影响这一条：记一条"出现错误"，QQ 连接不受影响 |

## 日志与排查

| 位置 | 内容 |
|---|---|
| `<数据目录>/ai-sidecar.log` | 每次 AI 请求一行：`complete provider=… model=… chars=… images=…` |
| 事件页 | 判定来源、耗时、失败与重试过程 |
| 设置 → 调试 | 手动测试解析、查看日志 |

**判断"到底有没有走 AI"**：先看事件行的耗时（几百毫秒 = 本地判定），
再对 `ai-sidecar.log` 里的请求行。

| 现象 | 原因与处理 |
|---|---|
| 分类偶尔判错 | 端点不稳定导致降级；看事件行是否写了"本地判定"，必要时换端点 |
| 模型返回空内容 | 推理强度过高或端点异常；边车会重试，仍失败则转人工 |
| 图片消息没被解析 | 模型不支持图片，或图片下载失败（>4MB、直链取不到） |
| 换课总说"缺少节次" | 课表接口不可用（ClassIsland 未连接 / 当天没有课表） |
