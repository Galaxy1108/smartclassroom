# 设置项说明

> 每个设置项的含义、功能开关的前置门槛、管理员密码、热应用、单实例、持久化。

## 设置项说明

设置页每项只留一句基本说明（写"这项是干什么的"）；具体行为、原理与取舍都记在这里。

## 功能开关：默认全部关闭

装完**什么都不会做**——不会被读群消息后自动发通知、改课表、下文件。五个开关在
设置页最上方，逐项开启（开启即保存，重启生效）：

| 开关 | 开启后做什么 | 关闭时 |
|---|---|---|
| 召唤通知 | 「xxx 来一下」→ ClassIsland 通知（上课排队，带「现在」立刻发） | 不发通知 |
| 作业自动录入 | AI 整理老师作业上墙到「作业」页 | 不上墙（可用「手动添加作业」） |
| 换课自动处理 | AI 解析后交插件校验，**合法才落课**（临时层） | 绝不下发到插件 |
| 群文件自动归档 | 老师发的文件按**科目**分类下载 | 连取下载直链都不做 |
| 上课课件弹窗 | 上课时弹「您可能需要的课件」 | 不弹 |

未开启的功能命中关键词时，事件页会记一条「『xxx』未启用，已跳过」（同类只提示一次，不刷屏），
这样"老师说了话但没反应"有据可查。

### 前置依赖：集成没配好就不允许开启

这些开关都依赖外部集成，依赖不满足时开着也只是空转（收不到消息 / 发不出通知），
所以设置页会**禁用对应开关并写明缺什么**，绕过界面直接赋值也会被拒绝、不会落盘：

| 开关 | 前置依赖 |
|---|---|
| 召唤通知 / 作业自动录入 | QQ 连接（OneBot 地址 + 监听群号）、AI（模型，内置直连还要服务地址） |
| 换课自动处理 | 上面两项 + ClassIsland 集成（桥接 token） |
| 群文件自动归档 | QQ 连接（不需要 AI） |
| 上课课件弹窗 | ClassIsland 集成（不需要 QQ/AI） |

依赖是**动态**判定的：把群号清空，已开启的「召唤通知」会被自动关掉并记一条日志，
避免留下"看起来开着、其实空转"的状态。缺什么直接写在对应开关下面（开关同时置灰），
不再单独放一条总览提示——那只是把同样的字再说一遍。

### 改了设置不用重启（热应用）

老师名单、群列表、功能开关以前都是**启动时的快照** —— 改完必须重启，
用户看到的现象是"我都把老师加进去了怎么还被当陌生人"（实测踩到）。现在：

- **老师名单**：保存后立刻重载（`TeacherMap.Reload`）；
- **功能开关**：保存后立刻更新（`PipelineService.UpdateFlags`）；
- **群列表 / 监听开关**：每条消息都读当前设置。

## 关闭行为与管理员密码

- **关闭主窗口默认收回到托盘**（托盘菜单可重新打开或退出）。托盘在部分 Linux 桌面环境不可用，
  此时自动退化为「关闭即退出」，不会出现关不掉的情况。设置页另有「退出应用」按钮作为第二条退出路径。
- **管理员密码**（PBKDF2-SHA256，随机盐 10 万次迭代，只存哈希不存明文）：
  设置后，改设置、切换功能开关、增删作业、处理待确认事项、以及**彻底退出**都需要验证。
  验证一次后 10 分钟内免重复输入；但**退出永远重新询问**。
  设置密码后立即生效（无需重启），且当前会话保持已解锁，不会被自己锁在外面。

### 管理员密码：默认每一次操作都要输

设了管理员密码后，**默认每一次修改操作都要重新输密码**，包括：

- 设置页的任何改动（含启动/停止 SnowLuma、安装插件、清空日志、清空所有设置）；
- 作业页的手动添加/编辑/删除/拖拽排序；
- 事件页的重新解析、人工补录、忽略、清空时间线。

**解锁窗口默认 2 分钟**：每次要做需要密码的操作都会先验证，刚验证过的一小段时间不重复问
（想更严格就把窗口调小，想省事可以打开「解锁后 10 分钟内免重复输入」）。
输错密码会有明确提示（连错 3 次提示稍后再试）。

> 没设密码时一切都不拦 —— 所以"密码没管住任何东西"通常是**还没设置密码**。

### 谁有权触发（默认只认老师名单）

**换课会真的改课表**，所以默认开启「只处理老师名单里的消息」：名单外的人发来的
换课/作业/召唤**不自动执行**，转人工确认（事件页会记一条，待确认里能看到）。

- 判定方式：QQ 号 / 群名片 / 昵称任一命中「老师映射」即认作老师；
- 老师名单为空时不做过滤（否则刚装好什么都用不了）——所以**配好名单再开功能**；
- 想放开就关掉这个开关（设置 → QQ 连接 → 只处理老师名单里的消息）。

## 单实例

不允许同时开两个智慧课堂。两个坑都踩过，所以现在是三重保障：

1. **命名互斥量**（跨进程），但它在 Unix 上和"持有它的线程"绑死——线程一退就失效，
   实测出现过两个实例同时在跑，所以不能只靠它；
2. **独占锁文件** `<用户数据>/SmartClassroom/.instance.lock`（`FileShare.None`，进程级、由内核持有）
   —— 这个是主力；
3. 第二个实例给出提示后**强制 `Environment.Exit(0)`**：只调 `desktop.Shutdown()` 不行，
   第二个实例没有主窗口，Shutdown 不会真的结束进程，提示窗会一直挂在屏幕上
   （用户看到的就是"多开没被拦住"）。

提示窗**不进任务栏**（`ShowInTaskbar=false`），否则任务栏多一个图标，同样像"没拦住"。
多开会抢同一个 SnowLuma 进程、同一个 5199 桥接端口、同一份 `state.json`（后写的覆盖先写的）。

## 持久化

作业、待处理事项、事件时间线写入 `state.json`（`~/.local/share/SmartClassroom/`），
30 秒定时 + 退出时落盘，写入用「临时文件 + 原子替换」。手动添加作业后立即落盘。

选 JSON 而非 SQLite：数据量小、零额外依赖、不引入 SQLite 原生库、出问题可直接打开看。
坏文件不会导致启动失败，会另存一份 `.bad` 供排查。

### 为什么"填好的 API Key 更新后又没了"

设置页与 Runtime 以前各持一份 `AppSettings`：设置页把 key 写进 `settings.json`，
而退出时 `Runtime.Stop()` 又拿**启动时装载的那份旧快照**覆盖了同一个文件 ——
于是每次正常退出（更新、重启）都会把本次会话的改动回滚。现在两者共用同一个对象，
退出时的再存一次只是把同一份数据写回，不可能互相覆盖。

顺带修掉两个相关坑：

- **手打的字段不用"碰巧触发别的保存"才落盘**：服务地址 / API Key / 模型 / 群号 / token / 端口
  改成 600ms 防抖自动保存；切页、关窗口、退出前会立刻 `FlushPendingSaves()`。
- **`settings.json` 也改成原子写入**，解析失败时把坏文件留成 `.bad`，
  不再"默默当没配过"——那等于把 Key 一起丢掉。

## 风险确认改成弹窗

「我已知晓风险」不再是一个随手能勾的小方框，而是**按钮 + 弹窗**：
点「启动」时若还没确认过，会先弹出完整封号警告，确认后才继续启动；
确认过之后按钮变成「重新查看」，随时能再读一遍原文。

## 调试设置

设置页最下方有「调试」区，目前只有一项：

- **清空所有设置**：确认后把 `settings.json` 恢复默认（AI / QQ / 归档 / 教师映射 / 功能开关 /
  管理员密码），并把**内存里那份也一起复位**——设置页与 Runtime 共用同一个设置对象，
  只删文件的话退出时又会被写回来。作业、待处理与事件时间线属于数据，不在"设置"范围内，不会被动。

## 设置页的操作反馈（应用内通知）

启动/停止 SnowLuma、下载 Node、AI 连通性测试、插件探测、保存设置这些**有副作用且耗时**的操作，
完成后都会在**右下角浮出一条应用内通知**（可手动关闭，5 秒自动消失）。
以前这些操作只有设置页里一行小字，用户看不到 → 以为点了没反应、以为失败。

通知复用 `NoticeBar` 的严重级别配色，所以一眼能看出是成功还是失败：

| 级别 | 颜色 | 例子 |
|---|---|---|
| 成功 | 绿 | SnowLuma 已停止 / AI 可用 / 设置已保存 |
| 警告 | 橙 | 已注入但服务未就绪 / 注入的账号与所选不一致 |
| 错误 | 红 | SnowLuma 启动失败 / AI 测试失败 / 打开目录失败 |

### 启动/停止/探测：按钮会转圈

SnowLuma 启动后要等 5 秒才探测、停止也要几百毫秒。这段时间三个按钮会**禁用并显示转圈**
（`启动中… / 停止中… / 探测中…`），避免"点了没反应"的错觉。

### 状态不再是含糊的一句话

运行状态、ClassIsland 连接状态、AI 测试结果都改成**图标 + 文案**的徽标（`StatusBadge`）：

- **对钩（绿）**= 在线 / 已连接且课表已加载 / AI 可用
- **感叹号（橙）**= 已注入但服务未就绪 / 插件连上但课表未加载
- **叉（红）**= QQ 未运行 / 未安装 / 探测失败 / AI 失败
- **信息（蓝）**= 探测中 / 未检测

原来的「已注入 / 服务未就绪」看不出算不算成功，现在用图标把三态分开。

## 作业过期：自动删除

作业的 `date` 语义是"**哪一天的作业**"：过了那一天就不再是"今天的作业"，所以直接删掉，
不保留历史（否则作业墙会一直堆积）。

- 清理时机：**启动时**一次 + **每 30 秒**一次（跨天不用重启）；连带 `state.json` 一起清。
- 每次清理都会在「事件」页记一条「已删除 N 条过期作业（科目…）」，不会"莫名消失"。
- 作业墙本身也再挡一道（`date < 今天` 不显示），避免清理还没跑到时闪过期卡片。
- 想要历史记录的话：作业内容在删除时会记进事件时间线，但**完整条目不再保留**。

> 注意：有卡片被挡掉时"可见卡片下标"与"存储下标"不一致，
> 拖拽排序按映射换算（`_visibleStoreIndex`），否则会挪错卡片。

### 科目颜色可以自己改

设置页 →「科目颜色」：把**当前作业里出现过的科目**列出来，每个科目一个颜色下拉
（`默认` = 按科目名稳定取色板颜色）。改完立刻生效（配色也算进卡片指纹，下一轮刷新就换色）。

### 外观

- **作业内容缩放**：只缩放「作业」页的卡片区（80%~180%），不影响导航栏、设置页等其余界面；
  也可以在作业页用 Ctrl+滚轮，设置会持久化。

## 界面与字体缩放

设置页「外观 → 界面与字体缩放」提供 80%~160% 滑块，改完立即生效、随设置持久化。
实现方式是 `LayoutTransformControl` 整体缩放：字号、图标、卡片一起放大，
**保住了主题原本的字号层级**（标题/正文/说明的相对大小），
比逐个覆盖 FontSize 更不容易把界面搞乱；卡片网格也会随缩放重新排列。

## 缩放范围

Ctrl+滚轮 / 设置页「外观 → 作业内容缩放」**只缩放「作业」页的卡片区**（80%~180%），
不影响导航栏、设置页等其余界面。

## 作业卡片

WinUI3 风格卡片：左侧按科目稳定取色的色条、相对日期（今天/明天/还有 N 天）、条目列表、
来源与条数。**按住卡片左侧手柄可拖动排序**，顺序随 `state.json` 一起持久化。

## 作业页布局

**响应式卡片网格**：卡片固定宽度 344，由 `WrapPanel` 按窗口宽度自动换行成多列，
窗口拉伸时列数跟着变（不是单列列表）。条目显示为 `1. 2. 3.` 编号。
拖动左侧手柄可重排——命中判断按**卡片实际矩形**做（X+Y），而不是只看 Y，
否则多列网格里会把不同列的卡片串在一起。

## 作业卡片拖拽（长按）

**长按卡片约 0.3 秒**进入拖拽。拖拽期间：

- 只有一张跟随指针的**"虚"卡片**（原始卡片压暗到 30%，不做缩放——缩放会溢出格子边界）；
- **目标位置用虚线边框指示**，框住将要落位的格子；
- **列表本身完全不动**，松手才真正落位（`MoveItemLive` 只调用一次）。

这样既没有卡片乱跳，也不需要在拖拽中反复改集合——而这正是之前丢指针捕获、甚至崩溃的根源。

**布局：瀑布流（`MasonryPanel`）**，不是 WrapPanel。WrapPanel 有两个浪费：

1. **右侧留白**——卡片固定宽度，塞不下下一列就空着；
2. **同行等高**——同一行里最高的卡片会把矮卡片撑高，下面留一大片空白。

瀑布流面板按可用宽度算列数、**卡片宽度拉伸填满整行**，并且**每列独立向下堆叠**，
矮卡片不会被旁边的超高卡片撑高。列数上限默认 4，可用宽度放不下时退化为单列。

**多行落位判定**用矩形命中（X+Y），不是只比 Y；落在行列间隙时回退到中心点最近的格子
（等距时取靠前的，保证稳定不抖动）。

注：Avalonia 会把子元素 Bounds 取整到整像素，所以边缘会有约 1px 的舍入差——
精确断言放在 `MasonryLayout` 的纯数学测试里，面板级测试用 1px 容差。

两个已修的坑（都会让拖拽表现异常）：

1. `PointerMoved` 在**只悬停不按键**时也会触发。若只判断"是否在拖拽中"而不检查左键是否仍按住，
   松手后会继续跟着鼠标重排 —— 现在每次移动都确认左键状态，一旦松开立即结束拖拽。
2. 拖拽中若调用 `Refresh()`（Clear + 重建卡片），**正在拖动的那张控件会被从可视树摘掉**，
   指针捕获随之失效、松手事件收不到，就会一直粘着鼠标。现在拖拽走 `MoveItemLive()`
   （只做 `ObservableCollection.Move`，复用现有控件），并在拖拽期间挂起定时刷新。

## 刷新的坑（拖拽失效 + 崩溃的根因）

主窗口有个 2 秒定时刷新。原实现每次 `Refresh()` 都 `Clear()` + 重建全部卡片，
于是**按住准备长按时卡片控件被销毁，指针捕获丢失 → 拖拽失效**；
在指针事件派发过程中销毁控件还可能**直接崩溃**。

现在三道防线：

1. **数据没变就不重建**（按内容+顺序算指纹），定时刷新绝大多数时候是空操作；
2. **从"按下"那一刻起挂起刷新**（不只是拖拽中），松手后强制补一次刷新；
3. **UI 事件全部 try/catch + 全局未处理异常拦截**（`Dispatcher.UIThread.UnhandledException`
   记入事件流且不退出进程），界面层异常不再能崩掉整个应用。

## 课件页：科目 → 时间轴

「课件」页分两层：

1. **科目卡片**：按科目分组，显示该科目的文件数与最近归档时间（没有科目的进「未分类」）；
2. **点进科目 → 时间轴**：按天分组（`2026-09-26 周六`），天内按**归档时间倒序**，
   左侧是时间轴竖线与圆点，行上是 `HH:mm` + 文件卡片（缩略图/类型徽标 + 文件名 + 大小），
   双击打开。「← 返回科目」回到第一层。

归档时间来自每个文件的 `meta.json`（`time` 字段）；老记录没有时间时归到「无时间记录」。
「预览上课弹窗」仍在第一层，用于手动看一眼上课弹窗的样子。
