# QQ / SnowLuma 集成

应用通过 [SnowLuma](https://github.com/SnowLuma) 连接 QQ：SnowLuma 负责登录与协议，
对外提供 OneBot 接口（HTTP + 正向 WebSocket），应用订阅事件、按需调用动作。
**不需要另外开一个 QQ 客户端。**

## 工作原理

```
QQ 服务器 ⇄ SnowLuma（登录 + 协议 + 注入 QQ 进程）
                 │  OneBot HTTP  :  发动作（发通知、取群列表、下载文件…）
                 │  OneBot WS    :  收事件（群消息、私聊、文件、图片…）
                 ▼
            智慧课堂 App  →  分类 / 归档 / 调 ClassIsland
```

应用做三件事：**启动并注入** SnowLuma、**订阅事件**、**按需调用动作**。
SnowLuma 的安装目录、注入状态、WebUI 密码都由应用代管。

## 首次配置

1. 设置 → **QQ 连接**，填写 SnowLuma 安装目录（应用会记住）；
2. 点「**启动注入**」：
   - 首次会弹窗让你确认 SnowLuma 的用户协议与隐私政策（不确认不会注入）；
   - 应用会顺手打开它的「自动注入」开关（也可以在它的 WebUI 里改回去）；
   - 注入成功后状态栏显示"QQ 已连接"；
3. 点「**自动分配端口**」：应用扫描本机可用端口，写进 SnowLuma 配置，
   并把 OneBot 地址与令牌填回设置；
4. 选择**班级 QQ 账号**（多账号时必须选一个）；
5. 在「老师映射」里加上老师的 QQ、姓名、科目（默认只处理名单里的人）。

## 端口与令牌

SnowLuma 为每个账号起一对 OneBot 服务：

| 用途 | 默认端口 | 说明 |
|---|---|---|
| HTTP | 3000 / 3010 / … | 动作调用 |
| 正向 WS | 3001 / 3011 / … | 事件推送 |

**HTTP 与 WS 的令牌是分开的**（`httpServers[0].accessToken` 与 `wsServers[0].accessToken`）。
只填一个会导致 WS 握手 401、事件收不到而 HTTP 动作正常 —— 现象很像"连上了但没反应"。
设置页因此提供两个令牌输入框，「自动分配端口」会把两个都填好。

配置文件位置：`<SnowLuma>/config/onebot_<QQ号>.json`。

## 监听范围

设置 → **QQ 连接 → 监听范围**：

| 开关 | 说明 |
|---|---|
| 监听群号 | 点「选择群…」从群列表勾选；只处理这些群的消息 |
| 监听全部群 | 处理所有群（慎用） |
| 监听老师私聊 | 处理老师的私聊消息 |
| 只处理老师名单里的消息 | 默认开；名单外的人一律忽略（含私聊） |
| 由 AI 判定老师消息 | 默认开；关掉则只用本地关键词 |

没监听的群也会在事件页留一条"**已忽略（该群没有监听）**"，方便确认消息确实收到了。

## 文件与图片归档

开关：设置 → **群文件自动归档**。开启后老师发的文件与图片会：

1. 落到 `<归档根>/<科目>/<文件名>`（科目取自老师映射；没配科目就用老师姓名，都不认识则"未分类"）；
2. 元数据写到 `<归档根>/.smartclassroom-meta/<科目>/<文件名>.json`
   —— 科目文件夹里**只有真正的文件**，不会混进一堆 `.meta.json`；
3. 复制一份到**系统下载目录**（可在设置里关，默认开）：

   | 平台 | 目录 |
   |---|---|
   | Windows | `%USERPROFILE%\Downloads` |
   | Linux | `~/.config/user-dirs.dirs` 里的 `XDG_DOWNLOAD_DIR`，取不到则 `~/Downloads` |

   > 老师常直接在 QQ 里点开文件，而 QQ 只认自己下载目录里已有的文件 ——
   > 复制过去后 QQ 会立刻判定"已下载"。

4. 私聊文件与群文件都支持；消息里的**图片**同样会被下载归档。

重名会自动加序号（`name (1).ext`）；目录不可写则跳过，不影响归档本身。
归档结果会记进事件页（`已执行：已归档 · 文件名 · 来自某老师`）。

## 让 QQ 端显示"已接收"

应用直接拉取文件直链只是"旁观者下载"，QQ 客户端并没有接收，
所以老师那边可能一直显示"未接收"。归档时应用会额外：

1. 私聊文件**优先**通过 `get_private_file_url` 向 QQ 服务器要直链
   （群文件用 `get_group_file_url`，都没有才退回消息段里的直链）；
2. 调用 SnowLuma 的 `download_file`，由它的协议层自己下载；
3. 把这条消息标记为已读。

触发结果会写在事件行末尾：`… · 已请 QQ 端接收`。

> 说明：QQ 的"已接收"标记由客户端/服务器侧决定，SnowLuma 目前没有协议级的接收回执动作
> （它的动作表里只有消息已读这一类）。若行尾已显示"已请 QQ 端接收"而对方仍显示未接收，
> 可先让对方**重开聊天窗口**再看；仍不变则属于 QQ 侧行为，应用这边已尽力。

## 多账号与多实例

- 一台机器登过多个 QQ 号时，SnowLuma 会给每个号分配一对端口（3000/3001、3010/3011…），
  **一个端口只能给一个号**；
- 「自动分配端口」会跳过被占用的端口；
- 应用启动前会**探测 OneBot 端点**是否已在跑（跨平台，Windows 上没有 `/proc` 也能判断），
  已在跑就跳过启动，避免重复起实例抢端口；
- 已经手动启动的 SnowLuma 会被应用**接管**（不重复启动，只接管注入）。

## Linux 注入的前置条件

SnowLuma 注入 QQ 需要满足：

1. `kernel.yama.ptrace_scope = 0` —— 否则只允许跟踪自己的子进程，注入必然失败：

   ```bash
   # 临时
   sudo sysctl kernel.yama.ptrace_scope=0
   # 永久
   echo 'kernel.yama.ptrace_scope=0' | sudo tee /etc/sysctl.d/99-snowluma.conf
   ```

2. SnowLuma 的「自动注入」开关（应用点「启动注入」时会替你打开）。

另外应用**不重定向** SnowLuma 的输出：曾经把它接到管道里，结果 QQ 进程退出时
触发 EPIPE 日志风暴（单日 291MB）。

## 排查

| 现象 | 原因与处理 |
|---|---|
| 状态栏"QQ 未连接"但消息一直在收 | 单条消息处理异常曾掀翻事件循环（已修）；现在单条异常只影响这一条 |
| WS 401 / 收不到事件 | HTTP 与 WS 令牌不同，两个都要填；或地址与令牌来自不同账号 |
| 收到消息但"已忽略（该群没有监听）" | 该群不在监听列表，用「选择群…」加上 |
| 「忽略陌生人私聊 <QQ>」 | 该 QQ 不在老师映射里；加进映射或关掉「只处理老师名单里的消息」 |
| 自己发的文件被当成课件 | 已修：`post_type: message_sent` 的自发消息一律忽略 |
| 注入失败（COMPONENT_LOAD_FAILED） | 见 [Linux 注入的前置条件](#linux-注入的前置条件) |
| 文件没保存 | 看事件行：`已忽略（发送者不在老师名单里）` / `已忽略（该群没有监听）` / `出现错误：文件归档失败` |
| WebUI 密码不生效 | 只有 `config/webui.json` 不存在时环境变量才生效；应用会先备份并删除该文件再播种 |
